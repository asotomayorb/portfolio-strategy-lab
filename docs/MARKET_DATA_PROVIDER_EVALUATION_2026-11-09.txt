MARKET DATA PROVIDER EVALUATION — 2026-11-09
================================================

STATUS
------
Technical evaluation only. No live provider has been connected, no API key is stored in the repository, and no provider is yet approved for production use. This work does not freeze or select a Phase 2 strategy and does not unblock Phase 3 execution.

CURRENT PORTFOLIO DATA SCOPE
----------------------------
The current portfolio_allocation.csv contains 13 instruments:
- US-listed securities/ETFs: VT, SMH, INDA, MSFT, NVDA, AVGO, GLD, URA, XLE, VHT, PLTR, QQQ.
- Crypto: BTCUSD (normalized to BTC in the historical ticker loader; provider symbol expected to be btcusd).

Cash is not a market-data instrument.

ARCHITECTURE DECISION
---------------------
Market data must come from an external market-data provider, independent of the broker adapter and independent of TradingView.

Keep three separate responsibilities:
1. Market Data Provider: historical OHLC, current reference prices, timestamps, market/session state and data-quality metadata.
2. Broker Adapter (initially IBKR): account positions, cash/buying power, pending orders, contract identifiers, executable quotes/order validation, order submission and fills.
3. Strategy/Order Engine: consumes normalized market data and broker account state; it must not depend on a specific vendor or broker implementation.

External market-data prices are inputs for signals and valuation. They are NOT assumed to be executable prices. Immediately before an order proposal/submission, the broker adapter must independently validate the instrument, trading session, executable bid/ask or relevant order reference, available funds, position and pending orders. Any stale, missing, crossed, malformed or materially discrepant price must block the order and raise a visible data-quality state.

PROVIDER CANDIDATE: TIINGO
--------------------------
Tiingo is the first candidate for a controlled proof of concept, not a final production selection.

Relevant documented capabilities:
- 24x5 Consolidated Real-time US equity REST and WebSocket endpoints, described by Tiingo as available on every self-serve plan, including Starter.
- The consolidated equity stream publishes a derived reference price (tngoLast), not a promise of executable NBBO or a raw full-market trade tape. It is intended for reference pricing, valuation and risk metrics.
- Tiingo Crypto provides consolidated crypto prices, top-of-book and historical intraday OHLC data; BTCUSD is documented as the btcusd pair.
- Individual Starter is listed at USD 0/month and Power at USD 30/month. Starter has lower API limits and five years of price history; Power has higher limits and 15+ years.
- Individual plans are for personal/internal use only. Do not redistribute or expose raw provider data publicly.

Official documentation:
- https://www.tiingo.com/documentation/equity-realtime-stock-data
- https://www.tiingo.com/documentation/websockets/equity-realtime-stock-data
- https://www.tiingo.com/documentation/crypto
- https://www.tiingo.com/pricing
- https://www.tiingo.com/documentation/general/changelog

WHY IT IS THE FIRST CANDIDATE
-----------------------------
It appears to cover the portfolio's two market-data needs with one vendor family: US-listed equity/ETF reference prices and BTCUSD crypto prices. Its current self-serve pricing and limits make a personal-use proof of concept inexpensive. Five years of history is sufficient in principle to warm up the 20-week ATR and 52-week swing-high calculations, but actual endpoint entitlements and symbol coverage must be tested.

UNRESOLVED / MUST PASS BEFORE ADOPTION
--------------------------------------
1. Authenticate and request each of the 12 US-listed symbols individually; record exact symbol, venue/asset type, returned fields and entitlement status.
2. Authenticate BTCUSD crypto REST and WebSocket requests; confirm pair metadata, quote currency USD, OHLC interval support and timestamp semantics.
3. Verify the 24x5 US equity REST and WebSocket endpoints return usable reference prices for every holding, including ETFs.
4. Measure actual update latency, missing/stale periods, reconnect behavior, rate limits and market-closed behavior over a representative observation period.
5. Confirm daily historical OHLC coverage and corporate-action/adjustment semantics are suitable for the weekly Wilder ATR and confirmed HH52 calculation. Do not silently mix adjusted and unadjusted series.
6. Compare selected provider prices with IBKR quotes during overlapping market hours; define instrument-specific discrepancy tolerances before enabling order proposals.
7. Verify the current Tiingo terms and exact plan entitlements before deployment. No public display, redistribution or multi-user use is assumed.
8. Keep provider tokens outside GitHub, source files, logs and browser code. Use environment secrets and redact credentials from errors.

ALTERNATIVES RETAINED
---------------------
- Twelve Data: broad multi-asset API and WebSocket coverage, but current individual plans list USD 79/month for Grow; Basic has only eight daily API credits and eight trial WebSocket credits. Its US real-time equity feed is sourced from venues representing about 5% of total US trading volume, so the exact feed quality/plan needs careful validation.
- Alpaca: viable for US equities/ETFs and crypto, but the Basic stock feed is IEX-only and the all-US-exchange SIP feed is a paid tier. It is less attractive as the single source for this portfolio without additional coverage checks.
- Massive: strong US equities data candidate, but crypto coverage and cost/entitlements need separate validation.

NEXT IMPLEMENTATION GATE
------------------------
Do not wire a live vendor into the strategy or order path yet. First perform the authenticated symbol/endpoint coverage test and a short data-quality soak test. If Tiingo passes, implement it behind a vendor-neutral MarketDataProvider interface with mocked unit tests, then add a read-only Streamlit market-data diagnostics screen. Do not alter Phase 1/Phase 2 engines or generate/send live orders in this step.

Phase 3 remains blocked pending the user's explicit freeze of the operating rule set and all protocol safety gates.


ADDITIONAL CRYPTO DATA CAVEAT
-----------------------------
Tiingo's Crypto Top-of-Book endpoint documentation now carries a deprecation warning because cross-exchange bid/ask construction has been unreliable. The proof of concept must use the Crypto Prices endpoint for last-price/reference and OHLC data only; do not rely on Tiingo for a consolidated BTC bid/ask. IBKR must provide the executable BTC quote/order validation if the selected IBKR instrument supports it. If IBKR cannot provide a suitable executable quote for the chosen BTC instrument, BTC order proposals remain disabled until a separately validated execution-price source is selected.


READ-ONLY REST COVERAGE PROBE
-----------------------------
A credential-safe diagnostic has been added at scripts/validate_tiingo_coverage.py. It reads the current portfolio_allocation.csv, checks the 12 US-listed symbols against the 24x5 reference-price REST endpoint and daily OHLC history endpoint, and checks BTCUSD via the Crypto Prices endpoint plus daily OHLC history. It prints a sanitized JSON summary and never prints or stores the token. Run it locally with TIINGO_API_KEY set in the environment:

  TIINGO_API_KEY=... python scripts/validate_tiingo_coverage.py

The probe does not test WebSocket continuity/latency, does not validate executable prices, and does not authorize order generation. Its pure helper functions have unit tests in tests/test_tiingo_coverage.py. Live REST validation remains pending until a user-owned API key is configured in the execution environment.
